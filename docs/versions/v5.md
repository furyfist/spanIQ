# spanIQ v0.5.0: Change Detection, Component Blame, Judge Escalation

**Status:** on `main`, not tagged or published yet (2026-10-20)
**Tests:** 426 passing (v0.4.0 had 244)
**Commits:** 24 (12 for the correctness pass, then 12 for the revamp)

---

## What's new

v0.5 changes the question spanIQ answers.

| Version | Question |
|---|---|
| V1 | Is this output good? |
| V2 | Is my LLM still good? |
| V3 | What broke, when, and what's cascade? |
| V4 | How do I get this into my stack, see it, and prove it's better? |
| **V5** | **Did my pipeline change, which component changed, and which traces should a judge look at?** |

v0.4 claimed spanIQ could replace an LLM judge for single outputs. Once the benchmark was fixed, that claim did not survive (see "Why the revamp" below).

v0.5 goes after what deterministic statistics are actually good at:
- spotting a shift across *many* outputs on 100% of traffic for $0
- naming the pipeline component it came from
- spending judge calls only on the traces that moved

---

## Why the revamp

The v0.4 benchmark had two bugs that together produced a false headline.

1. **Judge scores were made up under rate limits.** When a Groq call failed, the runners recorded a neutral `0.5`. On the summarization and RAG sets, 47 of the 48 judge scores were these fallbacks, which made the judges look like they collapsed.
2. **spanIQ's perfect score was a label leak.** Every "good" row was the reference answer copied word for word, so similarity scored it exactly 1.0.

After both were fixed and the benchmark was re-run with a live judge (`openai/gpt-oss-120b`; Groq retired `llama-3.3-70b-versatile`):

| Set | LLM judges (F1) | spanIQ similarity |
|---|---|---|
| qa_factual | 1.000 | F1 0.879 |
| summarization | pending quota | AUC 0.25 (worse than chance) |
| rag_retrieval | pending quota | AUC 0.06 (worse than chance) |

The reason is structural. An answer that copies the reference and adds an invented claim is *more* similar to the reference than a faithful paraphrase. Similarity to a reference cannot catch the most common way LLMs fail, so the per-output similarity approach had to stop being the product.

## Part 1: correctness and honesty pass

These were fixes to existing behaviour, made before the revamp.

| Area | Fix |
|---|---|
| Benchmark judges | Retry with exponential backoff; a call that still fails raises `JudgeError` and the tool is skipped with a printed reason. Permanent 4xx errors are not retried. No fabricated scores. |
| Benchmark data | Good summarization and RAG rows are hand-written paraphrases, not copies of the reference. |
| Alerting | One alert per incident instead of one per failing trace (`repeat_every` re-alerts during long incidents). Alerts are written to SQLite, so the dashboard's Alert Log works. Importing the module no longer rewraps `sys.stdout`. |
| SQLite | One `connect()` helper: WAL, 30 s busy timeout, commit or rollback, always closed. `BaselineStore.update` is atomic (`BEGIN IMMEDIATE`). |
| OTel receiver | Thread-safe trace assembly, real OTel trace IDs, ISO timestamps, OTLP/HTTP protobuf and gzip, 4xx on bad payloads, bind errors raised at start, localhost by default (`--host`), a short grace period for late child spans, current `gen_ai.input/output.messages` attributes read. |
| Collectors | Langfuse reads every page without repeating the boundary row, and message lists become text. The file collector in tail mode waits for half-written lines. |
| Metrics | `ConsistencyMetric` uses a one-sided KS test with a threshold that adapts to sample size. `OutputStabilityMetric` gives graded scores. Baseline embeddings are cached, and the model loads once under concurrency (`SPANIQ_EMBEDDING_MODEL`). |
| Attribution | Component breaks are aligned by trace ID, the pipeline filter is honoured, and online CUSUM is calibrated from observed scores. The unused `window_size` / `--window` are removed. |
| CLI | `--store-only` writes JSONL, `--pipeline` / `--name` work, unknown metric names are rejected, `--db` works after the subcommand, errors print one line. |
| Packaging | Apache-2.0 `LICENSE` added. Demo outputs are kept out of the wheel. matplotlib moved to the `viz` extra. CI tests Python 3.10 to 3.12 and checks wheel contents. |
| Dashboard | The Overview page no longer sleeps and reruns forever (auto-refresh is a toggle). Headless AppTest coverage. |
| Docs | README and `BENCHMARK_ACCURACY.md` carry a dated correction of the invalid table. The "1,000 cases in 4 seconds" claim was dropped (measured 24 s). |

## Part 2: the revamp, phase by phase

### Phase 0: drift benchmark harness

The harness was built first, so every later change could be measured against it.

- **`spaniq.signals.text`** computes 17 reference-free numbers per output:
  - size: chars, words, sentences, words per sentence
  - layout: lines, list lines, headers, code blocks, JSON validity
  - behaviour: refusal, hedges, questions
  - character mix: digits, uppercase, non-ASCII
  - style: lexical diversity, trigram repetition
- **`benchmarks/drift`** replays retrieval → generation trace streams through a detector:
  - each run is 100 baseline traces, 200 unchanged traces, then 300 traces with a change switched on
  - scenarios are built from the labeled datasets; a `control` scenario never changes, so every alarm on it is false
  - the `legacy` detector is the v0.4 approach: per-output `OutputStabilityMetric` plus "3 failures in a row"
  - a modeled table compares detection delay and cost against sampling an LLM judge at 1%, 5% and 20%
  - `--live` builds the same scenarios from real model calls by changing pipeline config: shuffled or truncated retrieval, a bullet-list prompt, a smaller model, a verbose prompt (`benchmarks/drift/live.py`)
  - `--save-traces` / `--traces` store streams and replay them
- Scenarios:

| Scenario | What changes | Cause |
|---|---|---|
| retriever_degraded | wrong passages; model refuses or invents facts | retrieval |
| context_truncated | context cut to 80 chars; short, hedged answers | retrieval |
| partial_retriever | 30% of retrievals wrong; answers unchanged | retrieval |
| prompt_format_change | answers become bullet lists | generation |
| model_swap | terse, hedged, sometimes invented facts | generation |
| verbose_drift | long, repetitive answers | generation |
| fact_swap | half the answers keep shape but get wrong numbers and names | generation |

`partial_retriever` and `fact_swap` were added after the first run showed the legacy detector caught every structural change instantly. These two change content only, so they separate a detector that reads content from one that reads shape.

### Phase 1: grounding signals and a grounding benchmark

- **`spaniq.signals.grounding`** checks an output against the context it was given, which every RAG trace already has. No reference answer is needed.
  - `unsupported_numbers`: share of the output's numbers absent from the context (`8,000` and `8000` match)
  - `unsupported_names`: share of mid-sentence capitalised words absent from the context
  - `novel_words`: share of content words absent from the context (a drift signal only, see results)
  - `question_coverage`: share of the question's content words found in a retrieval or tool span
- **`spaniq.signals.extract`**:
  - `trace_signals(trace)` returns signals for the final output and for every component span
  - retrieval and tool spans are checked against the question; other spans are checked against the outputs of the retrieval and tool spans before them
  - spans also get `error` and `latency_ms`
  - `context_for(trace)` uses `metadata.context`, otherwise the retrieval and tool outputs
- **`spaniq.signals.nli`** adds sentence-level groundedness:
  - each output sentence is scored by its best-supporting context chunk with a local NLI cross-encoder (`cross-encoder/nli-deberta-v3-small`, override with `SPANIQ_NLI_MODEL`)
  - it goes through sentence-transformers, which is already a dependency, so there is no new package, only a model download on first use
  - a sentence's contradiction score comes from the chunk that is least neutral about it, so an unrelated chunk cannot flag a supported sentence
  - all pairs go through one batched call
- **New metrics:**
  - `GroundednessMetric`: mean NLI entailment
  - `UnsupportedClaimsMetric`: lexical, no model

  Both work in `evaluate()`, `Monitor` and `--metrics`. `Monitor` now passes the trace's context as `retrieval_context`.
- **`benchmarks/grounding`** has loaders and scorers:
  - loaders: RAGTruth (from a local clone), HaluEval qa / summarization / dialogue (local), LLM-AggreFact (local export or Hugging Face hub), and the repo's own labeled rows
  - scorers: `unsupported_claims`, `novel_words`, `nli`, `judge`
  - it reports AUC and best-threshold F1
  - run it with `spaniq benchmark --suite grounding`
- **`Trace.from_dict()`** now holds the JSONL → `Trace` parsing that the file collector used to do inline, so every command shares it.

### Phase 2: window drift and `spaniq diff`

- **`spaniq.drift.compare(baseline_rows, candidate_rows)`** tests every signal present on both sides:
  - a two-sample KS test, with Benjamini-Hochberg adjustment across signals
  - a standardised mean difference (capped at ±99 for signals that were constant in the baseline)
  - a PSI that compares flags and counts as categories

  A signal counts as **drifted only if it is significant (alpha 0.01) and large enough** (|d| ≥ 0.5 or PSI ≥ 0.2). Without the size gate, big windows flag every negligible wobble. A test checks exactly this case (5,000 vs 5,000 traces, 0.15 σ shift: significant, not drifted).
- **Embedding MMD** (`mmd_test`): an RBF kernel with the median-heuristic bandwidth and a permutation p-value, for shifts in meaning that leave length and wording statistics alone.
- **`WindowDriftDetector`** keeps a sliding window against a fixed baseline. It checks every `stride` traces and returns a report only on the check where an incident starts; the incident ends at the first clean check.
- **`spaniq diff BASELINE CANDIDATE`**:
  - reports per component: stable or drifted, with the signals that moved
  - names the most upstream drifted component
  - lists the traces that moved furthest in the direction of the drift ("review first")
  - options: `--json`, `--markdown PATH`, `--embeddings`, `--nli`, `--top`, `--alpha`, `--min-effect`, `--min-psi`
  - **exits 1 on drift** so a pull request fails; `--no-fail` turns that off
  - when the final output only repeats a span's output, it is reported once
  - example GitHub workflow: `examples/ci/spaniq-diff.yml`
- **Monitors:**
  - `Monitor` and `PipelineMonitor` store every trace's signals as `signal.<name>` series in one transaction (`TimelineStore.record_signals`)
  - they raise one `drift:<unit>` alert per incident, written to JSONL and to SQLite with the component
  - `Monitor` compares reference-free signals against the stored baseline outputs; `PipelineMonitor` uses each component's warmup traces
  - `--drift-window` sets the window; 0 turns it off
  - `AlertEngine.alerts_path` may be `None`, so the pipeline monitor writes no JSONL by default

### Phase 3: attribution

The first version blamed the most upstream component that was *currently* drifting. On `retriever_degraded` it blamed generation every time.

The cause was dilution. Generation starts refusing and trips quickly, while the retriever's footprint (falling question coverage) is weaker. At trip time, the 100-trace window still held about 70 pre-change traces, which hid the retriever's shift.

**`spaniq.attribution.drift_attribution`** fixes this in three steps:
1. `estimate_change_start` finds where the tripping component's strongest signal changed (single-split binary segmentation, the statistic behind CUSUM change-point estimates).
2. Every other component is re-tested on only the traces since that point.
3. The most upstream component that shifted is blamed, and the verdict names the ones that followed.

Related changes:
- `PipelineMonitor` runs this on the first trip of each incident, adds the verdict to the alert message, and returns `PipelineReport.drift_attributions`.
- `spaniq attribute --signals` adds every stored signal series to the existing PELT/CUSUM attribution.
- `output_repeats_span()` drops the duplicate `output` unit when it is only the generation text. Before this, fact_swap was being blamed on "output".

This is ordering, not causal proof (see `docs/decisions/temporal-not-causal.md`).

### Phase 4: judge escalation

- **`JudgeBudget(db_path, daily_limit)`** is a daily cap kept in SQLite. Spending is atomic, so several processes sharing one database cannot overspend. The day rolls over at UTC midnight.
- **`GroqJudge`** has:
  - a support-and-correctness prompt that scores 1 to 10 and gives a one-line reason
  - retry with backoff, with no retry on permanent 4xx errors
  - a context cap
- **Selection and escalation:**
  - `drift_priorities()` ranks traces by summed, capped z-scores along each drifted signal's direction
  - `select()` takes the top k, with an optional random exploration share
  - `escalate()` judges within the budget, skips failed calls without inventing a score, and stores verdicts as the `judge` series
- **Wiring:**
  - `spaniq diff --judge groq --judge-budget 20` (budget kept in `--db`); verdicts appear in the console, JSON and Markdown
  - `spaniq monitor run --judge groq --judge-budget 50 --judge-per-incident 5` judges the window's top traces at the start of each drift incident

 JSONL file ──────┼──▶   text, grounding, NLI ──▶  baseline: KS + FDR +  ──▶  upstream attribution
 Langfuse, SDK ───┘      stored as signal.*        effect size, MMD           judge escalation (budgeted)

## Results

### Drift benchmark (synthetic streams, 10 seeds)

| Scenario | Legacy detected | Legacy delay | Legacy root | Window detected | Window delay | Window root |
|---|---|---|---|---|---|---|
| control (false alarms / 1k) | 0.0 | | | 0.0 | | |
| retriever_degraded | 100% | 2 | 0% | 100% | 29 | 90% |
| context_truncated | 100% | 2 | 100% | 100% | 29 | 100% |
| partial_retriever | 0% | | | 100% | 94 | 0% |
| prompt_format_change | 100% | 2 | 100% | 100% | 29 | 100% |
| model_swap | 100% | 2 | 100% | 100% | 29 | 100% |
| verbose_drift | 100% | 2 | 100% | 100% | 29 | 100% |
| fact_swap | 0% | | | 90% | 119 | 100% |

- **Detection:** the window detector caught 69 of 70 changed runs, all within 200 traces, with 0 false alarms in 5,000 unchanged traces.
- **Blame:** it named the right component in 58 of 69 detections (84%); legacy got 40 of 50 (80%).
- **Speed:** legacy is faster on shape changes (2 vs 29 traces).
- **Blind spots:** legacy misses content-only changes entirely.
- **Open gap:** the window detector still cannot attribute a retriever that fails on only 30% of queries. Half the items are summaries with no question words to check coverage against.

**Against a sampled judge (modeled, not run):** at 5% sampling, a judge needs about 67 to 200 traces after a change to collect 3 flags, at $0.0082 per 1,000 traces.

### Grounding benchmark (local labeled rows only)

| Scorer | n | AUC |
|---|---|---|
| unsupported_claims | 32 | 0.734 |
| novel_words | 32 | 0.131 |

- `unsupported_claims` scores 0.73 on the same rows where v0.4's similarity metrics scored worse than chance.
- `novel_words` is inverted because faithful paraphrases use new words, so it is kept as a drift signal only.
- 32 rows is not enough to conclude anything.

## Upgrade notes

- **More rows per trace.** `Monitor` and `PipelineMonitor` write about 20 extra timeline rows per trace (`signal.*`). They show up in the dashboard's metric pickers. Pass `record_signals=False` to skip them.
- **Drift alerts are on by default.** Turn them off with `--drift-window 0` or `drift_window=None`.
- **`AlertEngine.fire_drift()`** is new. `Alert` gained a `component` field (default `"default"`).
- **OTel receiver** binds to `127.0.0.1` unless you pass `--host 0.0.0.0`.
- **Removed:** `window_size` and `--window`. They never did anything.
- **Scores mean something different.** `ConsistencyMetric` and `OutputStabilityMetric` changed, so thresholds tuned on v0.4 need rechecking.
- **matplotlib** is now in the `viz` extra.
- **Model downloads.** The NLI and embedding models download on first use, only when you use `--nli`, `--embeddings`, `GroundednessMetric` or the similarity metrics.

## Known limitations

- Drift results come from synthetic streams whose scenarios we wrote, so they show the mechanics work, not real-traffic accuracy.
- A retriever that is wrong on a minority of queries is detected but not attributed.
- `spaniq diff` blames by pipeline order only; it has no time axis.
- The lexical grounding signals catch invented numbers and names, not reworded false claims. That is what the NLI tier is for, and it is unmeasured on public data.
- Judge escalation ships with Groq only.
- The Streamlit `use_container_width` deprecation warnings remain.
